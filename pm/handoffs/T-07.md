## Bot behaviour (interpretations)
- Greedy: every candidate scored by payback `T = wait + (cost − requestBonus)/ΔShells/s` (wait = time to afford at current income; fish gain × expected frenzy factor 1.67, fare gain = Δappeal × fare-per-appeal-per-second). Buys best if affordable, else saves. Level-ups (+1 and to-next-milestone) chain up to 25 per second; structural buys 1/second. Carriage/slot plans count the follow-up fish in their cost/gain but only execute the first step. Candidates: buy fish into each free-slot car, sell-weakest+buy (replace), carriage, slot, decor (buy / place from tray), habitat change, track (fare Δ + next station's species), Today's Special (free slot, shiny egg, level discount if savings×0.5 > price; never cosmetics), free moves. Request bonus = reward value if the change newly meets an open request on a current-line board.
- Reset rule: projected ≥ 2× totalTicketsEarned (≥ 3 first run); once reset-ready except for the terminal, only track + purchases repaying within 120 s. Upgrades strictly in table order. Newest opened Line. Mascot = highest-level fish (ties: basePps).
- Bond-never: same planner; fish valued by raw output + habitat (no bonds), car chosen randomly among free home-habitat cars, moves only to fix habitat.
- Random: every 3 s uniform over non-empty affordable categories (fish, level, carriage, slot, decor buy/place, track, move, upgrade), reset 50% when available (random mascot, random opened line); feeds a random car every 3 s; 50% of tap Sights.
- Metric definitions are in the report's "Definitions" section.

## Results
See `docs/qa/balance_report.md` (headline numbers in the final report). Biggest data causes: ticket sqrt curve explodes across Lines (2 resets suffice); Line 3 entry wall (1.5e12 first species vs ~1e8/s carried income) only broken by a lucky Stowaway → Terminus bimodal; fares ~1–2% because appeal never scales with level; requests 180–300 s rewards too generous/variable.

## Performance
Quick `--games 200` (800 games) ≈ 75–105 s wall on this shared 4-core box (load 3–8 from other agents). Full 5000 × 4 = see report header (seconds). CPU ≈ 0.25 s/game; ~100 ms of that is the sim itself.
