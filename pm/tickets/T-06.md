## Goal
Extend the T-05 sim (same API style, extend the Action/Event unions) with every remaining rule. Story JSON must be injected like data (add `story` to the createSim options or a `ContentData` bundle), not imported inside sim.

## Rules
1. **Sights** (`sights.json`): one every U(70,110) s seeded (Brass Bell: interval ÷1.5), one active at a time. `sightStart`/`sightEnd` events. Actions `tapSight{}`. Dolphin (tap within 8 s → +60 s of fish income), Seagull (6 s; untapped → lose 5% current shells), Whale Breach (×2 income 20 s, auto), Festival (next arrival fares ×5), Stowaway (8 s tap window; random species of an owned/unlocked habitat already bought this run or available on this line → free fish into a free slot; needs a free slot), Sea Fog (fares ×0.5, fish ×1.5, 30 s).
2. **Depot Reset**: `canDepotReset()` = runShells ≥ 1e6 && reached any terminal this run. `projectedTickets()` = floor(sqrt(runShells/1e5)). Action `depotReset{mascotFishId, mascotName, nextLine}` → resets run state per SPEC, keeps permanent block, keeps Heritage Carriage (carriage 1: habitat, decor layout, cosmetics) and Mascot (species, shiny, name; starts next run at level 5 in heritage car, ignores habitat penalty, Old Friend +25% after same species 3 resets in a row). Next run: 150 shells (+ Spare Change 500 × totalTicketsEarned), track to station 2 built, chosen opened line. `depotReset` event.
3. **Upgrades** (`upgrades.json`): `buyUpgrade{id}` with Tickets, each once; apply effects (season_pass offline 12 h / 70%, spare_change, express_engine leg 30 s, fishmonger −25% species costs (buy + level), double_decker 5 starting slots, brass_bell, ticket_printer fares ×2, matchmaker +25 pp pairs / +50 pp communities).
4. **Lines**: `chooseLine` only via depotReset; endless mode after ending: fares ×2.
5. **Offline**: `advanceOffline(seconds)` → cap (8 h / 12 h), earns rate × fishSps × t + rate × (farePerArrival / (leg+stop)) × t computed at current state; returns `{seconds, shells, stationsVisited}`; does not move timed buffs beyond expiry weirdly (expire them). Does not change train position meaningfully (advance phase modulo cycle is fine).
6. **Save/load**: `serialize()` has `version: 1`; `migrateSave(raw: unknown): SaveData` handles missing fields/older versions (write a fake v0 fixture in tests); invalid JSON → fresh game.
7. **Station markets** (B4.12): on each arrival build `market` state for that station: fish stall (signature species of that station + 2 species from earlier stations of this Line, deterministic), decor stall (3 seeded items from this Line's decor + plant pool, rerolled each arrival), Today's Special (one of: −30% on one owned species' next 10 levels / Shiny Egg for a chosen species already in the Catalogue or the signature species / free extra slot for a car / a cosmetic backdrop or paint not yet unlocked; price ≈ `todaysSpecial.priceSecondsOfIncome` × current totalSps, min 50), and the Requests board. Market persists until next arrival. `buySpecial{target?}`. Catalogue = species bought this run + decor owned. `buyFish` for a not-yet-bought species requires it to be in the current market's fish stall.
8. **Requests** (`src/story/requests.json`): each station shows up to 3 requests of its Line (station-specific first, deterministic), `acceptRequest{id}` optional (or auto-active — choose simplest: all board requests are active), completed automatically on arrival at that station when condition is met → reward (income seconds × current totalSps; cosmetic unlock; Shiny Egg; decor item into Catalogue/inventory) and `requestCompleted` event with passenger + carId; refresh after 2 visits; history kept across resets. Track `incomeFromRequests` in lifetime stats.
9. **Lifetime stats**: total shells, by source (fish, fares, requests, sights), per-species shells this run (for E1 dominance metric), time played, resets count.
