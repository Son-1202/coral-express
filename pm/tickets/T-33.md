## Problem
The spec gate is "runShells ≥ 1M and any terminal reached", but with the T-20 per-Line divisor the first Ticket on Line 1 needs ~8M run Shells, and the T-22c guard disables the button at 0 Tickets. Bots hit it in ~15 min; a real player at ~1.2K/s waits over an hour, with no number shown.

## Fix
1. **Rule:** when `canDepotReset` (≥ `minRunShells` this run AND a terminal reached this run), the reset grants `max(1, floor(sqrt(runShells / divisor)))` Tickets. Keep `projectedTickets()` consistent (the preview shows the real grant). Unit tests: eligible at 1M → 1 Ticket; below 1M or no terminal → not eligible; large runs unchanged.
2. **Depot panel clarity:** replace the vague hint with a checklist + preview:
   - "Reach the terminal (Station 6) this run" ✓/✗ (with current furthest station),
   - "Earn 1M Shells this run: 2.4M / 1M" ✓/✗ (run Shells, not wallet Shells),
   - "Reset now: +N Tickets · income ×A → ×B · next Ticket at X Shells".
   All numbers from the sim (no hard-coded values). Button enabled exactly when the sim allows a reset.
3. **Balance:** rerun `npx tsx scripts/balance.ts --games 200`; greedy bot behaviour may change (it already waits for ≥ 2× tickets). Report the 14 E1 rows before/after; keep the 12 passing rows passing (if one regresses, tune the bot's reset rule or the divisor minimally and document it in TUNING.md).
