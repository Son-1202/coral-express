# T-02 — CONTENT: GDD + all numeric data files + schema
**Role:** CONTENT · **Effort:** medium · **Phase:** 1
**Owned paths:** `src/data/**`, `docs/content/GDD.md`
**Read first:** CLAUDE.md, pm/STATE.md, docs/content/SPEC.md (all of B4, B5, E1).

## Goal
Every number and table from the spec as typed JSON data that the sim (T-04) will read. Faithful to the spec values (no tuning yet).

## Deliverables
1. `src/data/schema.ts` — exported TS interfaces for every file below (no runtime deps) plus a `GameData` aggregate type and `import` helper `loadGameData()` that imports the JSONs statically (Vite/TS `resolveJsonModule`).
2. JSON files:
   - `config.json`: startShells 150, startTrackStation 2, legSeconds 45, stopSeconds 6, maxCarriages 8, carriageBase 400, carriageGrowth 5, startSlots 3, maxSlots 6, slotCostFactor 0.5, slotGrowth 2, decorCapacityBase 6, decorCapacityPerSlot 2, habitatChangeFactor 0.2, copyCostGrowth 1.5, levelCostGrowth 1.15, maxLevel 50, milestones [10,25,50] ×2, offHabitatMult 0.5, fareAppealFactor 8, stationMults [1,1.4,2,2.8,4,6], frenzy {mult 3, seconds 10, cooldown 30}, shinyChance 0.01, shinyAppealMult 3, sightInterval [70,110], depotReset {minRunShells 1e6, divisor 1e5}, ticketIncomePerTicket 0.10, offline {rate 0.5, capHours 8}, sellRefund 0.5, decorCopyGrowth 3, communityBonus 1.0, communityAppeal 5, mascot {startLevel 5, oldFriendStreak 3, oldFriendBonus 0.25}, request {refreshVisits 2}, endless {fareMult 2}, todaysSpecial {priceSecondsOfIncome 120, levelDiscount 0.3, levelDiscountCount 10}.
   - `species.json`: 18 entries: id, name, habitat ('reef'|'mangrove'|'kelp'|'polar'|'vent'|'any'), line (1-3), station (1-6), baseCost, basePps, appeal, motion (profile per SPEC table), flags {firstFree?, sessile?, appealCount? (krill=2), alwaysHome?, perDistinctSpeciesBonus? (whale 0.05)}.
   - `bonds.json`: pairs [{a,b,bonus}], communities [{id,name,members[3]}].
   - `decor.json`: 14 items with id, name, pool ('l1'|'l2'|'l3'|'reward'), baseCost, capacity, appeal, isPlant, effects (structured: {type:'carIncome',value} | {type:'habitatIncome',habitat,value} | {type:'frenzySeconds',value} | {type:'bondBonusPP',value} | {type:'hide'}), sway preset for plants. Plus `plants.json`: the 20 plant sprites (4 per habitat, ids `<habitat>_<n>` with names, e.g. reef: sea fan, staghorn coral, sea grass, bubble coral; mangrove: mangrove shoots, red algae, turtle grass, sponge; kelp: tall kelp strand, kelp cluster, bull kelp, sea lettuce; polar: ice-weed, frost anemone, polar sponge, white sea pen; vent: tube garden, sulfur bloom, jade mineral spire, ash fern), each +1 appeal, capacity 1, cost scaled to its Line pool, sway {freq, amp} (kelp tall+slow, seagrass quick+short, coral fans barely move). Map listed decor plants to plant sprites where they match.
   - `upgrades.json`: 8 Depot Upgrades with structured effects.
   - `lines.json`: 3 lines: id, name, region, habitats unlocked, fareMult, trackBase, trackGrowth 8, opensAfter, decor pool id, palette hints.
   - `sights.json`: 6 sights with id, name, durationSeconds, effect params, requiresTap, tapReward.
   - `cosmetics.json`: 5 sand colors (hex), 8 exterior paints (hex), backdrops: per habitat default + 2 variants (ids `backdrop_<habitat>_<v>`).
3. `docs/content/GDD.md`: ≤ 2 pages summarizing systems and every formula with the data keys that drive them, plus a "tuning knobs" list.
4. Validate: write a tiny `src/data/validate.ts` (pure TS) that checks referential integrity (bond species exist, etc.) — DEV will call it from a unit test later.

## Acceptance
- JSON parses; values match SPEC exactly; schema.ts compiles under strict TS (run `npx tsc --noEmit -p .` if tsconfig exists; otherwise `npx -y typescript@5 tsc --noEmit --strict --resolveJsonModule --module esnext --moduleResolution bundler src/data/*.ts`).
